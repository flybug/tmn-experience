# 网络

网络拓先准备网络节点。节点可以是网元、板卡、端口，也可以是虚机，甚至是人眼看不到的一个业务端接点。以网元为例，一个网元及其所属的所有下属节点，形成一颗网元为根节点的单根树。
- 单根树有利于计算节点状态，以及方便生命周期管理
- 某些资源管理可能会打破单根树的关系，建议尽量转化为单根树

节点间的关系，假设我们命名为网络连接，网络连接将不同的网络节点关联在一起。网络连接可以是点到点，也可以是点到多点，甚至是一张网。不管是什么业务，或什么关系，都可以简化为网络连接。

## 常规属性

## Id
网络节点和网络连接，我们都可以称之为网络对象，而每一个网络对象都会有一个标识（Id）。Id是网络管理中最重要的属性，相当于身份证。
Id的几个难点
- Id的幂等带来很多好处，但也会导致Id长度的失控
  - 幂等的Id在处理网络连接的时候的优势非常明显，可以节省很多数据库的交互
  - 固定的网络节点的层次有利于构造幂等Id，例如NE/Rack/SH/SL这种结构。
- 雪花算法也是一个很好的选择，但失去了幂等的优势。推荐利用雪花算法的机制自定义Id格式

> 不管什么格式的Id，代码中只构造Id，强烈不建议对Id的含义进行解析。例如Id = NE-1/R1/SH1/SL1，通过Id得到该对象是Slot1，避免这种实现。</br>

## name
网络对象的名字用于帮助用户识别。名字可以修改，但并不用来做内部逻辑。为了管理方便，建议名字在一定范围内是唯一的。

## 网络节点
网络节点是网管的基础，所有的配置、告警和性能数据都会关联到一个特定的网络节点上
