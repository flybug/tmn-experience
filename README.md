# tmn-experience

# 前言
> **总结不含具体产品的技术方案和实现细节**

随着AI时代的到来，传统电信网管也面临转型，但电信网管的管理方式完全不适用了吗？趁此机会，总结自己在电信网管方面的经验，并探索AI方面的转型。希望在总结完结的哪一天，能找到这些问题的答案。
- AN (Autonomous Networks)的提出，带来了L0到L5的愿景，但如何落地？传统网管的管理逻辑如何演进？
- 传统的设备、业务管理方式真的可以完全演进为基于intent进行吗？
- LLM如何融入网管中？LLM的不确定性结果是否适用于严谨的网络管理？Agent，Harness，各种理论、框架等等是否适合网管管理逻辑？
- 目前可以看到一些关于故障预测和根因分析的模型训练的论文，除此之外，还有哪些场景适用于专有小模型的处理，从而让传统的网管逻辑有更好的实现方式。例如路由计算、趋势拟合、数据分析、扩容建议等等。
- 数字孪生的轻量级实现方案
- 一直的心魔：如何才能插件式的进行功能扩充，但又能保证软件架构的清爽，保持高效的执行效率，以及低资源的消耗。完美的目标是既要牛多产奶，还要少吃草。纯代码洁癖患者的念想
- 项目管理的难题（先记录，也许总结过程中突然想到新思路）
  - 想象是美好的，但最后结果总是会有或多或少的偏差
  - 团队人数稍微一多，开发时间一长，代码就呈现万紫千红的局面，而且重复逻辑，复杂的逻辑绕圈也快速多起来（熵增）
  - 沟通上的偏差

> 软件的思路都是通的，总结过程中，也许可以衍生出很多其他意想不到的思考和收获。<br>
> 软件在功能正确的情况下，实现方式和方案没有对错好坏。每个人的视角、思路和喜好不同，方案自然也不同。总结、讨论只为找到自己眼中的更优解。

**对产品最终呈现的设计，比完美的软件架构，使用最先进的技术等更重要。**
